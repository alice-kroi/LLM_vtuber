# AI 主播新技术的开发与优化方案

> 面向 LLM_vtuber 项目的下一代能力规划，聚焦 **记忆系统** 与 **思考方式** 两大核心，并延伸自主学习与 AI 直播专属体验。
> 本文档为**方案与路线图**，标有「✅已启用」「🟡部分启用」「🧭规划」三项状态，落地按章节三的优先级推进。

---

## 一、现状与差距分析

### 1.1 当前记忆系统

本项目已实现三层记忆，但各有局限：

| 层 | 实现 | 载体 | 现状问题 |
|----|------|------|----------|
| 短期记忆 | `MemoryManager`（InMemoryStore） | 内存 | 无法跨重启，结构扁平 |
| 长期记忆 | RAG（Milvus `chat_history`） | Milvus | 仅存历史问答，无知识语义分层 |
| 奖励/知识 | `reward_store` / `knowledge_store` + SQLite | SQLite | 🟡 本期新增，已跨进程持久化，但尚无「经验→技能」提炼 |

**核心差距**：记忆是「平铺的对话存档」，不是「结构化的知识/经验/技能」，也没有主动遗忘与反思。

### 1.2 当前思考方式

LangGraph 固定流水线：`init → load_memory → rag_retrieval → context_control → llm_process → save_memory → [live2d] → [tts]`。

- 单轮生成 + 最多 3 轮工具调用（`_run_doubao_chat` 循环）
- 有意图分类器（正则+嵌入），但**无自我反思、无多步规划、无结果自评**

**核心差距**：属于「一次成型」的前馈推理，缺少人类主播的「想想再说」「觉得不对再调整」。

## 二、技术优化方案

### 🔷 A. 记忆系统升级（Memory 2.0）

目标：从「存档式记忆」升级为「分层语义记忆」，支持**记忆→经验→技能→人格**的转化。

#### A1. 分层记忆架构（🟡→✅）

引入五层记忆，替代当前平铺结构：

```
┌──────────────────────────────────────────────────┐
│  L1 工作记忆   本弹幕回合的上下文（每次都重建）        │
│  L2 情景记忆   直播会话历史（InMemoryStore+SQLite）  │
│  L3 语义记忆   知识/见闻/设定（Milvus 向量检索）      │
│  L4 经验记忆   高奖励互动模式（reward→knowledge）    │  ← 本期已建
│  L5 程序记忆   技能/动作流程（工具调用习惯）           │  ← 新增
└──────────────────────────────────────────────────┘
```

**落地要点**：
- 检索时按 **L3→L4→L5 优先级降序召回**，token 预算按层分配
- L5 程序记忆：记录「在什么场景下调用什么工具/动作成功」，让主播学会「何时该卖萌、何时该搜索」

#### A2. 记忆反思压缩（🧭 新增，参考 Generative Agents 的 memory reflection）

- 定时（如每 10~20 回合）用 LLM 对近期对话做**反思**，产出概括性洞察
  - 例如：「观众今天多次提到『歌单』，说明他们喜欢听歌→ 沉淀为 L3 语义记忆」
- 反思结果写入 `knowledge_store`，供后续检索注入
- **关键**：反思要**异步**（复用现在的并行后处理机制），不阻塞首字响应

#### A3. 主动遗忘与衰减（🧭 新增）

- 记忆项增加 `last_access` 与 `importance` 两个评分
- **衰减规则**：间隔越久、被引用越少 → 检索权重越低 / 定期清理
- 避免「陈年垃圾记忆」污染上下文，符合真人主播「记不住是本能，记住重点才是能力」

#### A4. 记忆一致性锚点（✅ 已具备，强化）

- 身份设定 / 直播间人设作为 **L0 常驻锚点**，永不衰减
- 支持「开播前重置情景记忆、保留语义与程序记忆」——模拟真实主播每场上播重新开始但对长期人设/技能有记忆

### 🔷 B. 思考方式升级（Thinking 2.0）

目标：从「一次成型」升级为「感知→规划→行动→反思」的智能体闭环。

#### B1. ReAct + 自我反思（🟡→✅）

在现有工具循环基础上增加**反思环节**：

```
用户弹幕
   ↓
1. 感知   解析意图 + 相关记忆召回
   ↓
2. 规划   判断:直接答 / 搜索 / 调用工具 / 卖萌回避
   ↓
3. 行动   执行工具 or 直接生成
   ↓
4. 反思   对生成结果自评(是否偏离人设 / 是否满足弹幕)
   ↓
5. 修正   不满意 → 二次生成;满意 → 输出
```

**建议引入 `thinking_mode` 配置**：高频弹幕用轻量直答（当前模式），复杂/长回复启用反思。避免每句都反射，保证直播低延迟。

#### B2. Plan-and-Execute（🧭 新增，用于复杂任务）

- 当意图判断为 `force_search` / `reduce_rounds` 且任务复杂时，先让 LLM 产出**步骤计划**再逐步执行
- 例如「查最近关于 XX 的新闻并总结」→ 规划「①搜索 ②抓取 ③总结 ④用人设语气输出」
- 复用现有 `tool_dispatch_node` / `tool_registry`，仅在 `_run_doubao_chat` 增加 plan 分支

#### B3. 链式思维（CoT）受控启用（🧭 规划）

- 对**需要推理**的问题，允许模型先输出 `reasoning` 再给 `content`（参考已过滤 reasoning_content 的经验）
- **风险控制**：默认关闭，仅对少数枚举/计算/矛盾问题时开启，且对用户仅在最终输出呈现 content
- 避免 CoT 破坏人设语气与口语化

#### B4. 情绪与节奏感知（🧭 新增，AI 主播专属）

- 在 state 中加入**情绪节流器**：
  - 同一情绪类型（开心/撒娇）高频出现时，自动换一种语气，避免「审美疲劳」
  - 弹幕高潮（奖励正反馈激增）时，主播主动活跃/感谢
  - 低质量弹幕密集时，主播礼貌转移话题
- 复用 `reward_tracker` 的实时奖励信号作为「节奏开关」

### 🔷 C. 自主学习增强（Learning 2.0）

基于本期已建的 reward→feedback→knowledge 闭环，向纵深演进：

| 方向 | 现状 | 升级目标 |
|------|------|----------|
| 奖励循环 | ✅ 弹幕/礼物/SC → 打分 → 注入 | 加入**手动评分** WebUI 控件、精细化情感（未命中时 LLM 补判） |
| 知识沉淀 | ✅ 高奖励回复 → `knowledge_store` | 反思沉淀 + **竞争机制**（新知识 vs 旧知识同场景择优） |
| 程序学习 | 🧭 缺失 | 学习「高奖励场景下调用了哪类工具/动作」→ L5 程序记忆 |
| 反向学习 | 🧭 缺失 | 低奖励回复也记录 → 人工/自动标注避免重犯 |

### 🔷 D. 工具化 TTS（衔接前序 PR-1）

- 将 TTS 从「后处理节点」升级为 **ToolRegistry 工具**，LLM 可主动调用（朗读长文/播报搜索结果）
- **混合模式兜底**：LLM 未主动调用时仍自动播放，防哑播
- state 增加 `tts_called` 标记，避免重复合成

## 三、实施路线图

按「低风险高收益 → 中风险高价值 → 高风险创新」三阶段推进，每阶段可独立测试与回滚。

### 阶段一：稳地基（推荐先做）
| 编号 | 内容 | 优先级 | 涉及文件 |
|------|------|--------|----------|
| S1 | 分层记忆检索改造（L3/L4/L5 按权重召回） | P0 | `memory_manager.py`、`main.py` |
| S2 | 记忆反思压缩（异步，复用并行后处理） | P1 | `learning/`、`main.py` |
| S3 | 工具化 TTS + 混合兜底 | P1 | `tool/tool_node.py`、`main.py`、`LLM/LLM_node.py` |
| S4 | 情绪节奏器（复用 reward 信号） | P1 | `learning/`、`main.py` |

### 阶段二：提智能
| 编号 | 内容 | 优先级 | 涉及文件 |
|------|------|--------|----------|
| S5 | ReAct 自我反思（`thinking_mode` 开关） | P2 | `LLM/LLM_node.py` |
| S6 | Plan-and-Execute 分支 | P2 | `LLM/LLM_node.py` |
| S7 | 手动评分 WebUI + 精细化情感 | P2 | `webui/`、`learning/sentiment_scorer.py` |

### 阶段三：增创新
| 编号 | 内容 | 优先级 | 涉及文件 |
|------|------|--------|----------|
| S8 | L5 程序记忆（动作/工具习惯学习） | P3 | `learning/`、`live2d/` |
| S9 | CoT 受控启用 | P3 | `LLM/chat_model.py` |
| S10 | 主动遗忘与衰减 | P3 | `memory_manager.py` |
| S11 | 反向学习（记录低奖励避免重犯） | P3 | `learning/`、`main.py` |

> P0=最高优先，P3=探索性。建议按优先级排序，每个 S 项独立成小任务、可回滚。

## 四、技术选型建议

| 需求 | 推荐方案 | 理由 |
|------|----------|------|
| 记忆持久化 | SQLite（已用）+ 可选 Milvus | 零依赖、跨重启；海量语义检索再上 Milvus |
| 反思/提炼 | 复用现有豆包 LLM | 不引入新模型，成本可控 |
| 技能记忆 | prompt 注入 + 行为 profile | 比 RL 训练更现实（项目规模） |
| 低延迟 | 异步反思/学习 + `thinking_mode` | 直播场景首字响应是生命线 |
| 弹性架构 | 保持 LangGraph 图 + learning 模块 | 不重写主干，增量扩展 |

## 五、风险与对策

| 风险 | 后果 | 对策 |
|------|------|------|
| 反思/规划增加延迟 | 直播卡顿 | 全部异步化；默认轻量直答 |
| 记忆污染（错误反思知识点） | 人设崩坏 | 反思结果低置信度不注入；人设锚点永不衰减 |
| L5 技能记忆僵化 | 行为固化失去灵活性 | 引入探索率：偶尔偏离习惯动作 |
| CoT 破坏口语化 | 语气生硬 | 默认关闭，仅特定任务开启 |
| 工具化 TTS 漏调 | 哑播 | 混合模式兜底 + `tts_called` 标记 |

---

## 六、结语

本方案的核心是把主播从「单轮应答的聊天机器人」升级为
**「有记忆、会思考、能学习、懂节奏」的智能体**：

- **记忆**：从存档 → 分层语义 + 反思 + 主动遗忘
- **思考**：从一次成型 → 感知·规划·行动·反思
- **学习**：从被动记录 → 奖励闭环 + 程序习惯 + 反向学习

推荐从 **阶段一 S1/S2** 起步，它们是后续所有智能化的地基，风险最低、收益最直接。
