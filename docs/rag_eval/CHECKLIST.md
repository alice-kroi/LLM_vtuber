# RAG 评估检查清单（可执行版）

> 版本：v0.1　|　机器可读版本：`docs/rag_eval/checklist.json`　|　校验脚本：`scripts/check_rag_eval_checklist.py`
>
> 用法：每条检查项均含 **检查项 / 判定标准 / 验证方式 / 建议阈值** 四要素。
> 阈值状态三种：`已定`（可直接判定）、`待实测标定`（**当前一律不得作为通过/失败依据**，先测量再回填）、
> `参考区间`（外部资料给出的经验区间，仅供参考，需在本项目实测后收紧）。

## 一、约定与状态标记

- `[已定]`：阈值来源明确、可直接卡线。
- `[待实测标定]`：**检索类指标与全部阈值缺口统一使用此标记**。含义是“口径已定、数值未定”，
  必须先在本项目评测集上跑出基线分布（P50/P10），再回填为具体数值，并把状态改为 `已定`。
- 缺口回填流程：跑基线 → 记录 P10/P50 → 取 P10 作为回归红线 → 更新 `checklist.json` 的 `threshold` 与 `status`。

## 二、检索侧检查项（口径已定，阈值全部待实测标定）

| ID | 检查项 | 判定标准 | 验证方式 | 建议阈值 |
|----|--------|----------|----------|----------|
| R-01 | Recall@k（命中率） | 标准答案所在文档出现在 Top-k 的比例 | 用 `gold_doc_ids` 与检索结果前 k 名求交，命中即 1 | **待实测标定**（先用 k=5、k=10 各记录一次基线 P10/P50） |
| R-02 | MRR（平均倒数排名） | 首个相关结果排名的倒数的均值 | 取每个 query 第一个命中的 rank r，累加 1/r 后求均值 | **待实测标定**（记录基线，回归时不得低于基线 P10） |
| R-03 | NDCG@k | 按位置折损后的排序质量，与理想排序的比值 | 用相关度标签计 DCG@k，除以 IDCG@k | **待实测标定**（需先确定相关度分级口径：0/1 或 0/1/2） |
| R-04 | Precision@k（上下文信噪比） | Top-k 中相关条目占比 | 相关条目数 / k | **待实测标定** |
| R-05 | 检索延迟 P95 | 单次检索（含 embedding + 向量检索）P95 耗时 | 评测集全量逐条计时，取 P95 | **待实测标定**（先测基线，再按产品体感定线） |

## 三、生成侧检查项（Ragas 口径）

| ID | 检查项 | 判定标准 | 验证方式 | 建议阈值 |
|----|--------|----------|----------|----------|
| G-01 | Faithfulness（忠实度） | 答案中的陈述能被检索上下文支持的比例 | Ragas Faithfulness：答案切分为陈述，逐条判定是否被 context 蕴含 | **待实测标定** |
| G-02 | Answer Relevancy（答案相关性） | 答案与问题的贴合程度 | Ragas Answer Relevancy：由答案反向生成问题，与原问题算相似度 | **待实测标定** |
| G-03 | Context Precision | 检索上下文中真正有用部分的排位质量 | Ragas Context Precision | **待实测标定** |
| G-04 | Context Recall | 参考答案所需信息被检索覆盖的比例 | Ragas Context Recall：把参考答案切分后逐句判定是否可归因于 context | **待实测标定** |
| G-05 | 拒答行为 | 检索为空或相关度低于门槛时必须明说“没有依据”，不得编造 | 构造 5 条无答案问题，检查回答是否含拒答措辞且不出现事实断言 | **待实测标定**（拒答准确率基线需实测） |

## 四、切分与索引侧检查项

| ID | 检查项 | 判定标准 | 验证方式 | 建议阈值 |
|----|--------|----------|----------|----------|
| C-01 | Chunk 长度分布 | 分块长度落在设计区间内，无超长块压爆上下文 | 统计全部 chunk 的 token 数，输出 P50/P95/max | **待实测标定**（先测分布再定上限；超长块包括 `Lost in the Middle` 风险） |
| C-02 | Chunk 重叠（overlap） | 相邻块有重叠，避免句子被切断导致语义丢失 | 抽样 50 对相邻 chunk，检查尾部与首部是否重复 | **待实测标定**（重叠比例需实测权衡存储成本） |
| C-03 | 元数据完整性 | 每个 chunk 都能溯源到源文件 + 位置（doc_id、source、offset） | 遍历向量库，统计缺字段条目数，应为 0 | **已定**：缺失率 = 0% |
| C-04 | Embedding 模型一致性 | 索引与查询使用同一 embedding 模型与维度 | 比对向量库 dimension 与查询侧返回 dimension | **已定**：必须完全相等 |
| C-05 | 索引新鲜度 | 文档更新后能在约定周期内进入可检索状态 | 改动一条测试文档，轮询直到检索命中，记录耗时 | **待实测标定**（需先确定增量索引周期目标） |

## 五、评测集检查项

| ID | 检查项 | 判定标准 | 验证方式 | 建议阈值 |
|----|--------|----------|----------|----------|
| E-01 | 三元组字段完整 | 每条样本含 `question / reference_answer / gold_doc_ids`，可选 `contexts` | 逐条校验字段存在且非空 | **已定**：缺失率 = 0% |
| E-02 | gold_doc_ids 有效性 | 标注的文档 ID 在索引中真实存在 | 对全部 gold_doc_ids 查向量库是否存在 | **已定**：有效率 = 100% |
| E-03 | 题型覆盖 | 事实型 / 多跳型 / 无答案型 / 长尾专有名词型均有样本 | 按 `type` 字段统计各类占比 | **待实测标定**（先统计当前构成，再补齐短板题型） |
| E-04 | 规模 | 样本量足以让指标波动可控 | 统计样本总数，并对比两次重复跑的分差 | **待实测标定**（需实测不同样本量下的指标方差） |
| E-05 | 无答案样本比例 | 用于卡拒答行为的负样本不能被忽略 | 统计 `type == "no_answer"` 占比 | **待实测标定** |

## 六、工程与回归检查项

| ID | 检查项 | 判定标准 | 验证方式 | 建议阈值 |
|----|--------|----------|----------|----------|
| O-01 | 评测可复现 | 同配置重跑，指标漂移在可接受范围 | 连续跑两遍全量评测，比对各指标差值 | **待实测标定**（受 LLM 采样影响，需实测漂移带） |
| O-02 | 判定器一致性 | LLM 裁判的判定与人工标注一致 | 抽 30 条由人工标注，与裁判结果算一致率 | **待实测标定** |
| O-03 | 回归门禁 | 指标下降超过红线时 CI 必须失败 | 阈值回填后，在脚本里对指标做断言 | **待实测标定**（红线 = 基线 P10） |
| O-04 | 失败样例留存 | 未通过的样本必须落盘，便于定位 | 检查评测输出目录含 failed 明细文件 | **已定**：必须存在 |
| O-05 | 成本与耗时 | 单次全量评测的成本与时长在预算内 | 记录 token 消耗与 wall-clock | **待实测标定** |

## 七、阈值缺口汇总（全部待实测标定）

检索指标（R-01～R-05）与生成指标（G-01～G-05）的**数值阈值目前一律空缺**，
外部资料未给出可直接采用的区间，因此统一标记 `待实测标定`，不得凭感觉填数。

标定步骤：
1. 固化评测集版本（记录 `dataset_version`），保证前后可比。
2. 跑基线，导出各指标 P10 / P50 / P90。
3. 以 P10 作为回归红线，填入 `checklist.json` 的 `threshold`，把 `status` 改为 `已定`。
4. 每轮改动后重跑，红线未回填前，回归门禁（O-03）处于 `skip` 状态而非通过状态。
